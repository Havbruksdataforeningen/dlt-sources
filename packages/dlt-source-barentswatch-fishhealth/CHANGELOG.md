## [Unreleased]

### Added

- Initial release: a dlt source for four endpoints of the BarentsWatch Fish Health API, one resource each, named after its endpoint. `localities` and `localities_with_salmonoids` are the API's two locality lists — the register list with municipality, about 2 700, and the salmonoid list lice reporting applies to, about 2 000 — loaded with `replace` when selected ([which is which](CONTEXT.md#places)). `locality_week` is the detailed weekly report per locality — lice counts, lice treatments, diseases, escapes, control areas and the aquaculture-register entry — one request per locality-week, iterating over the salmonoid list. `locality_week_summary` is the weekly summary of every locality matching a filter, from `POST /v2/geodata/fishhealth/locality/{year}/{week}`, one request per week: the same lice report, diseases and lice treatments as names only, none of the register, zone or escape fields. Rows land as the API returns them, plus the key both weekly tables merge on, `localityNo`, `year`, `week`, so the two join — [which to load for what](REFERENCE.md#the-summary-and-the-detail).
- Two arguments: `week_range` on both weekly resources, and `body` on the summary — the spec's `LocalityReportQueryV2`, sent as given, bound in code or set in `.dlt/config.toml` under `[sources.barentswatch_fishhealth.locality_week_summary.body]`. Everything else is dlt's: keep some localities with `add_filter` on `localities_with_salmonoids`, stamp a row with `add_map`, run the summary once per filter value — [Configuring a resource](README.md#configuring-a-resource).
- Five examples: [`discover_localities.py`](examples/discover_localities.py) prints the salmonoid list to pick localities from, [`backfill.py`](examples/backfill.py) loads them back to 2012, [`weekly_load.py`](examples/weekly_load.py) re-loads the last four complete weeks on a timer, and [`production_areas.py`](examples/production_areas.py) loads the summary of two production areas, one run per area, with the area stamped on each row. [`organization_weekly_load.py`](examples/organization_weekly_load.py) is the last two together for one company: a summary request finds every locality under an organisation number, `locality_week` loads those in detail, and the summary loads the production areas around them.
- `WeekRange`, `last_n_weeks`, `current_iso_week`, `weeks_in_year` and `FIRST_YEAR`, for building the week range both weekly resources need — the API is addressed by ISO year and week, with no window parameter and no cursor.
- [REFERENCE.md](REFERENCE.md) holds the operational detail — the locality-week row, nesting, the lookback and backfilling, why HTTP 400 is skipped, and what the source deliberately does not expose — so the README stays a first read.
- [API quirks worth knowing](specs/README.md#api-quirks-worth-knowing) records where the live API departs from its own OpenAPI document, in ways that reach you as a consumer.
- [Compatibility](README.md#compatibility) records which Fish Health API version the package is built and verified against. This release targets the `v1` spec, endpoints `GET /v1/geodata/fishhealth/localities`, `GET /v1/geodata/fishhealth/localitieswithsalmonoids`, `GET /v2/geodata/fishhealth/locality/{localityNo}/{year}/{week}` and `POST /v2/geodata/fishhealth/locality/{year}/{week}`.
- The package ships a PEP 561 `py.typed` marker, so your type checker reads its annotations instead of treating it as untyped.
